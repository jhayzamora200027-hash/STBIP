Security headers — staging & production
-------------------------------------

This project includes two places to enforce HTTP security headers:

- Application-level: `app/Http/Middleware/SecurityHeaders.php` — applied by Laravel for responses generated by the app.
- Server-level: `docs/security/apache-security-headers.conf` — include this in your Apache site configuration to cover early responses, static assets, and redirects.
- Server-level: `docs/security/nginx-security-headers.conf` — include this in your nginx server block when the app is served behind nginx.
- Server-level: `docs/security/nginx-tls-hardening.conf` — include this in the nginx TLS `server {}` block to disable CBC suites and static RSA key exchange on TLS 1.2.

Recommended deployment steps

1. Deploy the app changes staging environment and clear caches:

   ```bash
   composer install --no-dev --optimize-autoloader
   php artisan config:clear
   php artisan cache:clear
   php artisan route:clear
   php artisan view:clear
   ```

2. Copy the Apache snippet to the server and enable it (example for Debian/Ubuntu):

   ```bash
   sudo a2enmod headers
   sudo cp docs/security/apache-security-headers.conf /etc/apache2/conf-available/stb-security.conf
   sudo a2enconf stb-security
   sudo systemctl reload apache2
   ```

   For nginx deployments, include both nginx snippets inside the TLS `server {}` block and reload nginx:

   ```bash
   sudo cp docs/security/nginx-security-headers.conf /etc/nginx/snippets/stb-security-headers.conf
   sudo cp docs/security/nginx-tls-hardening.conf /etc/nginx/snippets/stb-tls-hardening.conf
   sudo editor /etc/nginx/sites-available/your-site.conf
   sudo nginx -t
   sudo systemctl reload nginx
   ```

   Example TLS server block includes:

   ```nginx
   server {
       listen 443 ssl http2;
       server_name your-site.example;

       ssl_certificate /path/to/fullchain.pem;
       ssl_certificate_key /path/to/privkey.pem;

       include /etc/nginx/snippets/stb-tls-hardening.conf;
       include /etc/nginx/snippets/stb-security-headers.conf;

       # existing proxy_pass/root configuration...
   }
   ```

3. Verify headers with `curl -I` against your staging URL.
4. Verify that CBC and static RSA suites are no longer offered:

   ```bash
   nmap --script ssl-enum-ciphers -p 443 your-site.example
   openssl s_client -connect your-site.example:443 -cipher 'AES128-SHA' -tls1_2
   openssl s_client -connect your-site.example:443 -cipher 'AES256-SHA' -tls1_2
   ```

   The `nmap` output should show only `TLS_ECDHE_*` AEAD suites for TLS 1.2. The two `openssl` checks should fail the handshake once CBC and static RSA suites are disabled.

Notes and cautions

- The middleware reads `config/security.php` — strict headers (COOP/COEP/CORP/HSTS) are only applied when `app()->environment()` is one of `['production','staging']` by default.
- HSTS is only set when the request is TLS (`$request->secure()`). Only enable HSTS in production when you serve all traffic over HTTPS.
- Content-Security-Policy must allow the app's current dependencies: `cdn.jsdelivr.net`, `cdnjs.cloudflare.com`, `code.jquery.com`, Google reCAPTCHA (`www.google.com`, `www.gstatic.com`), `fonts.bunny.net`, `fonts.googleapis.com`, `fonts.gstatic.com`, `data:` images used for the favicon, same-origin SVG object embeds, and same-origin/HTTPS fetch targets. Tighten it further only after those assets are moved local or nonce/hash support is added.
- If `curl -I` reports `Server: nginx`, the Apache snippet will have no effect on that host. Use the nginx snippet instead.
- If a reassessment still reports `TLS_RSA_*` or `*_CBC_*`, the staging load balancer or reverse proxy in front of nginx is still terminating TLS with its own cipher policy. Apply the same AEAD-only, ECDHE-only policy there as well.
